Plan first, then apply. Hash manifests track managed output, detect drift, and keep updates idempotent.

Pluggable adapters

Use bundled runtimes, private JSONC file-drop adapters, or explicit local adapter code behind --allow-adapter-code.

Source drivers

Consume local paths, git packages, SkillKit sources, and Vercel-style skills without making the registry mandatory.

R

Asset-includes

Compose shared files into self-contained skills at staging time, preserving executable bits and hashing the final bundle.

P

Runtime targeting

Run inside a runtime folder with no target flag, or sync a named fleet with --agent, --all, and profiles.

How it works

Author package Skills, rules, instructions, and future artifacts live upstream.
→
Workspace control plane .agentwheel stores locks, overlays, overrides, and local intent.
→
Runtime output Sync writes generated files into the runtimes you use — OpenClaw, Claude, Codex, Copilot, Hermes, and any custom runtime you add via your own adapter.

How to add a package

Package discovery is powered by the public agentwheel registry. The registry is optional, but it gives users clean short names like agentwheel add nestdev-core-toolkit. Packages can also use asset-includes to keep one canonical copy of shared scripts while installing self-contained skills.

1 · Publish a package repo Add `agentwheel.json` plus folders such as instructions, rules, skills, commands, MCP, or hooks.
→
2 · Open a registry PR Add one entry to `index.json` in NestDevLab/agentwheel-registry.
→
3 · Install by short name Users run `agentwheel registry update`, then `agentwheel add <name>`.
index.json entry 
{
  "name": "your-package-name",
  "source": "github:your-org/your-agent-package",
  "type": "package",
  "description": "Reusable skills, rules, and instructions for agentwheel.",
  "tags": ["skills", "rules", "instructions"]
}
agentwheel.json assets 
{
  "type": "skills",
  "path": "skills",
  "assets": [
    {
      "from": "packages/tmux-bridge/bin",
      "into": "bin",
      "include": ["*.sh"],
      "mode": "preserve"
    }
  ]
}

Get started

agentwheel is early (v0.5) and installs from npm. Three steps: get it, point it at a package, preview the plan, then sync. In normal use you do not need --target-root.

1 · install 
$ npm i -g agentwheel
$ agentwheel --help
# pnpm user? `pnpm add -g agentwheel` works too
2 · add a source 
$ agentwheel init                              # create the .agentwheel workspace
$ agentwheel add github:your-org/agent-pack --adapter openclaw
$ agentwheel add ./my-pack --adapter hermes       # local source works too
3 · preview, then sync 
$ cd ~/.openclaw
$ agentwheel sync --dry-run    # auto-detects the runtime target
$ agentwheel sync              # writes into ~/.openclaw without nesting
fleet mode 
{
  "agents": {
    "lab-openclaw": { "adapter": "openclaw", "root": "/path/to/openclaw-home" },
    "docs-copilot": { "adapter": "copilot", "root": "/path/to/project" }
  }
}

$ agentwheel sync --agent lab-openclaw
$ agentwheel sync --all
# target order: --target-root > --agent > auto-detect cwd > cwd

Global fleet config lives at ~/.agentwheel/config.json; project config lives at .agentwheel/config.json and overrides it. Custom or private runtime? Skip the registry entirely and point at a local adapter: agentwheel sync ./my-pack --adapter-config ./my-runtime.jsonc. Contributor install from source: git clone ... && pnpm install && pnpm build.
