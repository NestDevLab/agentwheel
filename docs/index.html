Get started

agentwheel is early (v0.9) and installs from npm. Start with one package, or keep explicit control over add, plan, and install. In normal use you do not need --target-root.

Primary path 
$ npx agentwheel install nestdev-must-have
# resolved, locked & installed into your runtime — pick it with --adapter claude|codex|copilot|hermes|openclaw
Full control 
$ npx agentwheel init
$ npx agentwheel add github:your-org/agent-pack --adapter openclaw
$ npx agentwheel plan
$ npx agentwheel install
dependencies & trust 
$ agentwheel install --trust "github:your-org/*"  # pre-approve transitive sources
$ agentwheel deps tree                          # inspect the resolved graph
$ agentwheel deps why skills/triage             # why is this installed, and from where?
$ agentwheel install --offline                  # zero network, straight from the lock
fleet mode 
{
  "agents": {
    "lab-openclaw": { "adapter": "openclaw", "root": "/path/to/openclaw-home", "transport": "local" },
    "remote-codex": {
      "adapter": "codex",
      "root": "/home/agent/project",
      "transport": "ssh",
      "host": "agent-host.example",
      "user": "agent"
    }
  }
}

$ agentwheel install --agent lab-openclaw
$ agentwheel install --all
$ agentwheel install --profile daily --dry-run
# target order: --target-root > --agent > auto-detect cwd > cwd

Global fleet config lives at ~/.agentwheel/config.json; project config lives at .agentwheel/config.json and overrides it. Custom or private runtime? Skip the registry entirely and point at a local adapter: agentwheel install ./my-pack --adapter-config ./my-runtime.jsonc. Contributor install from source: git clone ... && pnpm install && pnpm build. Full docs live in the README.

Works with every runtime

Five complete built-in adapters, two ways to bring your own. Every adapter maps the full artifact model into the runtime's native layout — no generic dumps. Need another harness? Bring your own adapter via a JSONC config (--adapter-config) or a programmatic module (--adapter-module).

Claude and Copilot MCP merge JSON. Codex MCP updates only [mcp_servers] in config.toml, preserving unrelated user config.

How it works

Author package Skills, rules, instructions, and fragments live upstream — with declared dependencies on other packages.
→
Workspace control plane .agentwheel stores graph locks, overlays, overrides, trust decisions, and local intent.
→
Runtime output Install writes generated files into the runtimes you use — OpenClaw, Claude, Codex, Copilot, Hermes, and any custom runtime you add via your own adapter.

Plan first, then apply atomically. Hash manifests track managed output, detect drift, journal every apply for recovery, and keep updates idempotent.

Source drivers

Consume local paths, git packages, SkillKit sources, and Vercel-style skills without making the registry mandatory.

Selective installs

Install the exact artifacts you want with --select or --skill, while package-declared required artifacts stay protected.

P

Runtime targeting & fleet

Run inside a runtime folder with no target flag, or install into a named fleet — local and SSH — with --agent, --all, and profiles.

Built on OpenPack — packages that depend on packages.

OpenPack is the vendor-neutral package format behind agentwheel: one manifest for skills, rules, instructions, and shared fragments — with dependencies, composition, and runtime targeting. Any tool can implement the spec; agentwheel is the reference implementation.

G

Dependency graph, locked

Packages require other packages. agentwheel resolves the full graph recursively, dedupes npm-style where versions are satisfiable, and writes a deterministic graph lock — every machine installs the same thing.

∞

Fragment composition

Keep one canonical copy of shared guidance and transclude it at sync time with <!-- openpack:include --> markers — within a package or across dependencies, with provenance and drift detection on the result.

fragmentsinclude markersasset-includes
⛨

Trust & offline

New transitive sources never install silently — approve them once, pin a workspace trust policy, or deny artifact types outright. --frozen-lock and --offline give reproducible, zero-network installs.

How to add a package

A package is a git repo with an openpack.json manifest. Since v0.9, install reads the lock by default while update moves tracking sources forward. Discovery is powered by the optional agentwheel registry, which gives users clean short names like agentwheel add nestdev-core-toolkit; any git URL works without it. Browse everything installable — official packages plus curated Vercel and SkillKit skills — in the resource catalogue.

1 · Publish a package repo Add `openpack.json` plus folders such as instructions, rules, skills, commands, MCP, or hooks.
→
2 · Open a registry PR Add one entry to `index.json` in NestDevLab/agentwheel-registry.
→
3 · Install by short name Users run `agentwheel registry update`, then `agentwheel add <name>`.
openpack.json — dependencies & fragments 
{
  "schemaVersion": 2,
  "name": "your-org/agent-pack",
  "version": "1.0.0",
  "requires": {
    "core": {
      "source": "github:your-org/core-pack",
      "version": "^1.2.0",
      "select": ["rules/safe-actions.md", "fragments/risk.md"]
    }
  },
  "provides": [
    { "type": "fragments", "path": "fragments" },
    { "type": "skills", "path": "skills" }
  ]
}
# in a skill's markdown: <!-- openpack:include core:fragments/risk.md -->
index.json entry 
{
  "name": "your-package-name",
  "source": "github:your-org/your-agent-package",
  "type": "package",
  "description": "Reusable skills, rules, and instructions for agentwheel.",
  "tags": ["skills", "rules", "instructions"]
}
openpack.json assets 
{
  "type": "skills",
  "path": "skills",
  "assets": [
    {
      "from": "packages/tmux-bridge/bin",
      "into": "bin",
      "include": ["*.sh"],
      "mode": "preserve"
    }
  ]
}
selective install 
$ agentwheel add github:NestDevLab/agent-mesh --skill codex-tmux
$ agentwheel install --select rules/core-safety.md
# provides[].required artifacts are always installed
